## 目标与完成标准

面向具备基础 Go 知识、希望理解 Agent 设计思想的学习者，形成一条可以复现的路径：先运行一个无密钥的真实引擎回放，再沿模型候选、工具准入、执行观察、状态更新与停止原因理解 Harness，最后通过故障对照学习预算、上下文、恢复和协作的必要性与代价。

本轮交付以仓库可复现、教学分层和机制说明准确为完成标准。学习者应能完成以下任务：

1. 从干净检出构建并通过离线测试，无需本机私有夹具或模型密钥。
2. 使用一条命令观察真实引擎的一次“调用模型 → 执行工具 → 回传观察 → 交付”过程。
3. 根据回放证据解释：动作为什么被允许或拒绝、预算为什么耗尽、中断后为什么可以继续或必须停止。
4. 区分实现契约、确定性回归、真实模型采纳和语义质量结果，并找到对应源码及实验记录。

不设未经测量的学习耗时或性能提升承诺。模型调用费用为零的教学回放和离线检查优先；首次安装 Go 依赖可能需要访问模块代理，不把这一点称为全流程断网可运行。

## 设计取舍

七功能按本轮“教学入口与故障实验”评估：感知 Light（固定、小规模文本夹具）；记忆 Heavy（演示跨轮证据和恢复）；推理 Light（脚本候选可重复）；行动 Heavy（复用真实准入和文件工具）；反思 Light（观察拒绝与修正）；协作 None（首批课无需子任务）；治理 Heavy（临时工作区、权限、预算与停止边界）。协作课程在单体课程稳定后再纳入。

主拓扑沿用现有 ReAct 循环。教学入口只负责装配固定任务、脚本 Provider、真实 Registry、Session、Engine 和 Reporter，不复制第二套 ReAct 引擎。上下文、工具调度、进度追踪是首批优先解释的机制；在每一课中仅加载必要内容。

运行路径：

`选择课程 → 创建临时工作区与夹具 → 装配脚本 Provider 和真实引擎 → 模型候选 → 确定性准入 → 工具观察与状态更新 → 继续或停止 → 输出回放结论`

| 所有者 | 职责与边界 |
| --- | --- |
| 教学入口 | 选择场景、创建临时工作区、设置有限预算；不读取 `.env` 或选择远端 Provider |
| 脚本 Provider | 根据请求和前一工具观察产生预置候选；遇到意外轨迹明确失败，防止固定终答掩盖错误 |
| 现有 Engine / Registry | 管理真实上下文、权限、预算、执行、任务状态和恢复 |
| Reporter / 课程输出 | 展示公开事件和结果；执行状态与副作用状态分别输出，不以 `OnToolCall` 表示 Handler 已执行 |
| TaskStore / 版本回执 | 保存运行事实，恢复时继续使用真实状态与文件版本核对 |

## 分阶段实施

按 `M0 → M1 → M2 → M3 → M4` 顺序推进；前四阶段是本轮主体，M4 是后续扩展边界整理，不要求实施新运行机制。

### M0：恢复干净检出的可复现性（P0）

**改动**

1. 清点被测试读取的夹具及生成来源，核对现有合成、脱敏声明；纳入必要文件或提供确定性生成方式。不能直接把整个忽略目录无差别加入 Git。
2. 调整 `.gitignore`，保留对运行产物、密钥和本机数据的排除；夹具位于明确的已跟踪目录。
3. 增加干净检出检查入口和 GitHub Actions 工作流，使用 `go.mod` 声明的 Go 版本，不配置模型密钥；构建、普通测试及内部 race 分别形成可定位结果。
4. 在开发文档中解释“工作区通过”和“已跟踪源码可复现”的区别。

**验收**

- 必需夹具可通过 Git 文件清单确认，前述三组测试在隔离快照中使用 `-count=1` 通过。
- 完整构建、普通测试、内部 race 均在隔离源码中通过。
- 提交前使用“仅导出已跟踪文件并覆盖本次明确变更”的候选快照，不用包含全部本机文件的复制冒充干净检出。提交后再用 `git archive <提交>` 核对。
- 工作流定义可本地检查；只有远端实际执行后才能记录为 CI 通过。

### M1：增加无密钥最小回放与分层导读（P1）

**改动**

1. 新增 `cmd/learn` 作为独立教学入口，共用真实 `AgentEngine.Run`、工具和消息类型。首个命令为 `go run ./cmd/learn -scenario react`，现已实现。
2. 脚本 Provider 隔离在教学装配代码中，默认临时工作区；首次课程固定读取一个小文件并基于真实观察交付。
3. 输出模型请求序号、工具候选、观察和最终 `RunResult`，明确候选与实际执行的区别。复用现有 Reporter / 观测能力，不为排版修改引擎协议。
4. 新增 `docs/learning/README.md` 与 `docs/learning/01-react.md`，说明每一步的状态读写、源码入口、预期输出和自查题。
5. README 提供“无密钥回放 → 真实只读任务 → 工程约束 → 高级实验”的入口。核心导读标出首遍阅读路径，版本兼容与实验分支按需深入。

**验收**

- 不调用模型配置加载，不需要 API Key，只操作自动创建的临时工作区。
- 确认真实文件读取发生、观察以匹配的 ToolCallID 回到后续请求；脚本只在核对真实观察后交付。
- 未知场景、意外候选序列和执行错误以明确错误退出，不能打印成功示例掩盖失败。
- 学习者可对照输出找到入口、上下文构建、模型调用、工具准入、观察回传和退出位置。

### M2：建立故障与机制对照课程（P1）

先把已有关键回归组织为教学场景，再补缺失的对照。对照尽量采用相同脚本候选和输入；需要教学基线时只运行在隔离夹具内，不关闭主引擎的真实保护。

| 课程 | 注入症状与对照 | 验收证据 |
| --- | --- | --- |
| 预算与停止 | 脚本持续提出工具意图；比较不同有限额度 | 实际调用数不越限，终态及 StopCode 正确；收尾额度单独解释 |
| 权限与副作用 | readonly 下提出写入候选，再用合法读取继续 | 写入被拒、Effect 为 NONE、目标文件未改变；候选出现不等于 Handler 执行 |
| 上下文与证据 | 长读取导致窗口或字节预算压力，比较旧策略与当前有来源投影 | 消息配对完整；未处理来源不会被当前策略静默丢失；超限有明确停止原因 |
| 中断恢复 | 在临时任务中构造可核实文件效果与不可核实命令效果 | 文件按版本补记且不重复写；未知命令保持阻塞，不再调用模型或盲目重试 |
| 计划与依赖 | 计划含已完成步骤与待处理依赖，另给非法依赖 | 就绪步骤按依赖执行；已完成步骤保留；非法计划在动作前失败 |

每课统一包含“问题 → 最小基线 → 机制 → 观察证据 → 新增成本 → 保证边界 → 自查题”。固定回放证明结构约束，不证明真实模型质量或采纳率。

**验收**：场景可单独运行，错误路径可重复；断言围绕动作次数、文件版本、消息配对、预算和终态等不变量。对已有充分覆盖的逻辑复用测试，不为展示文本和实现细节增加重复测试。首批无需子 Agent 或真实模型；后续协作课须有上下文隔离和报告合并的具体问题。

### M3：校准机制说明与实验导航（P1）

**改动**

1. 为上下文、计划、恢复、协作和质量机制增加统一边界表：解决的问题、确定性保证、模型仍负责什么、失败出口、测试入口和真实验证状态。
2. 明确 `Compactor.mask` 的折叠 / 截取与有来源工作笔记的区别，说明字节上限与 Token 用量的区别。
3. 明确当前计划重排冻结 DONE，但尚无完整“仅修改失败子图、保留外部依赖”的补丁校验；明确步骤对话完成与业务验收的区别。
4. 明确 RecoveryManager 的提示补充与 TaskStore 的效果核对分别解决什么问题；本地文件版本核对不推广为远端业务幂等保证。
5. 调整实验导航，让学习者先读设计问题与结论，再按需查版本记录；历史失败、null、not_run 和原评分保持原义。

**验收**：每个重要保证都能追到源码或测试；未实现能力标为缺口，未取得有效真实结果标为待验证。文档中的命令、相对链接与实际接口一致。不能把通过格式、引用、算术或模型复核合并为“质量通过”。

### M4：整理扩展契约与后续改造入口（P2）

**本轮交付**

- 补充新工具扩展清单：注册、可见性、权限、只读分类、变更分类、预算、执行前记录、效果、恢复及子任务范围，并链接所有真实代码入口。
- 用一个小型工具示例核对当前“注册即可感知”的适用边界，说明 `scope.go` 和 `execution.go` 中按工具名分类的规则。
- 将工具元数据与局部计划补丁校验写成独立后续设计事项，不借教学文档调整批量改变执行语义。

**升级触发条件**

- 当新增工具实测需要修改多个分类位置、已有规则出现漂移时，再评估显式能力 / 副作用描述。候选为保留名称规则、引入可选元数据或扩展工具接口；优先比较兼容成本，不预定全量重构。
- 当需要支持受限局部重排时，再设计失败步骤身份、受影响子图、外部依赖和补丁上限，并确定旧任务恢复的版本策略。已有完成事实和未知效果仍由原恢复边界保护。
- 这些运行机制变更须有具体故障输入、兼容方案和独立回归，再进入实现；完成本轮教学目标不以新增上述机制为前提。

## 验证与交付节奏

建议按 M0、M1、M2 各课、M3、M4 分批形成可审阅变更；每批附问题、行为变化、验证结果及限制。明确选择变更文件，不使用 `git add .` 纳入既有工作。提交或推送实际发生前，不把候选工作区称为已发布版本。

| 变更范围 | 必需检查 |
| --- | --- |
| 纯文档 | 相对链接、命令与源码事实核对、`git diff --check` |
| 夹具 / 干净检出流程 | 缺失夹具回归；隔离快照的构建、全量普通测试及内部 race |
| 教学入口 / 回放 | 针对真实动作、消息配对、预算和终态的场景检查；相关包测试，再全量普通测试与构建 |
| 共享预算 / 账本 / 存储 / 审批语义 | 相关故障回归及 `go test -race ./internal/...` |

项目检查统一使用以下包范围：

```bash
go build ./cmd/... ./internal/...
go test ./cmd/... ./internal/...
go test -race ./internal/...
```

干净快照首次验收使用 `go test -count=1 ./cmd/... ./internal/...`，避免仅报告缓存命中。通过后仅在新改动、失败或仍有未解疑点时重复扩大检查。不得使用会纳入演示草稿的 `go build ./...` / `go test ./...`。
