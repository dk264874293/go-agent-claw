# 质量优先的分析与报告 v1

质量模式将重要发现、实际读取的证据、本地核验、模型复核和最终发布分别记录。它默认关闭，普通任务和历史任务沿用原行为。引用通过、指定数学关系成立、阅读完整及结论语义正确是不同结果；内部复核不会把任务升级为 `VERIFIED`。

程序保证、模型责任和失败出口见[机制边界](mechanism-boundaries.md#质量模式与普通交付前处理)，真实效果先读[实验导航](experiments.md)。

## 使用与兼容

```bash
# 只读分析，在控制台交付结构化发现
./claw -dir /绝对路径/资料库 -mode readonly -analysis -quality \
  -prompt "分析资料，列出有原文依据的重要发现和未确认边界"

# 在工作区新建证据报告，原资料不修改
./claw -dir /绝对路径/资料库 -mode workspace -report 优化汇总.md -quality \
  -read-scope docs -read-name-glob '*.md' -require-full-read \
  -prompt "完整阅读声明范围，生成精简报告"

# 恢复时不重复传 -quality，沿用任务持久策略
./claw -dir /绝对路径/资料库 -resume 任务ID
```

首版只支持 `readonly + answer + analysis` 或 `workspace + change + report`。不能组合规划、额外思考、验收命令或子任务委派；分析的默认委派自动关闭，CLI 可显式传 `-delegation off`。仅传 `-quality` 不会把普通任务自动转成分析或报告。CLI 在创建 Provider 前拒绝不支持的参数组合，引擎入口也重复校验。

报告目标仍须为工作区内新建的 `.md` 文件，父目录已存在，不能覆盖已有文件。质量模式不提高权限、读取页大小、共享预算或上下文上限。`-require-full-read` 仍须显式声明读取范围，不从任务文字补造范围。

Engine 使用 `TaskSpec.Quality = &QualitySpec{Version: 1}`；Bench 在分析或报告 `TestCase` 中设置 `Quality: true`。内置代码编辑评测不适用质量模式。飞书本轮只复用质量终报展示，没有新增启动配置。

## 流程和工具契约

```text
读取、必要复读和有来源的工作笔记
→ verify_findings 登记唯一草稿
→ 引用与本地检查
→ 按风险最多一次模型复核
→ 根 Agent 一次修订／提交
→ 程序复验、冻结渲染字节
→ 发布有效部分，或阻断并交付待核实项
```

`verify_findings` 只对质量任务可见，必须是当前响应的唯一工具，正常计一次工具尝试。参数包含 `schema_version: 1`、`findings`、可选 `overview_ids / unverified / checks`。发现保留既有 ID、类型、结论、短引用、依赖、版本及范围条件；比较和迁移沿用报告条件字段。草稿不可变保存，登记后关闭探索。重复提交不能重置核验次数。

每个 `QualityCheck` 通过 `finding_id` 绑定发现，检查自己的原文来源也须由该发现的引用锚定。`subject` 使用证据 ID 列表及文件绝对字节区间，不把行号当 offset，不解析工具输出头重建原文。长主体选择器独立于最多 1024 字节的短引文限制。核验工具只返回票据身份、状态、有界计数和问题摘要，详细计算与复核材料保存在受限任务证据中。

质量报告的最终 `write_report` 参数和质量分析的终答均采用：

```json
{"draft_id":"核验工具返回的草稿ID","corrections":[]}
```

`corrections` 每项包含 `operation` 和 `finding_id`：`replace / add` 提供完整 `finding` 及可选 `checks`，`unverified` 提供原因。不能再交一份自由报告绕过票据。复核响应以逐项 `supported / revise / unverified` 表达；精确修订可带同源 `replacement` 和对应 `checks`。新发现、改变的语义或检查不能继承旧复核回执。

发布仅使用被接受的发现和明确待核实项。正式数值公式及计算结果由解析后的 AST 和实际检查结果生成，本地免复核项的适用背景由引擎限定，避免自由文字夹入另一条未经检查的公式或运行结论。成功写报告后不再调用模型复述结果。

## 本地检查的证明边界

`internal/quality` 不依赖引擎、工具或 Provider，不执行资料脚本、任意表达式、Python 或多语言代码分析。

| 检查 | 支持内容 | 不代表 |
|---|---|---|
| 受限算术 | 变量、十进制常量、加减乘除及明确加总；精确有理数计算 | 模型对复杂代码、分支或默认行为的翻译正确 |
| 明确 JSON 对象 | 存在、不存在、类型、值相等、缺失时默认值；严格 JSONPointer | 一个样例可以证明整个文件、版本或系统不存在字段 |
| 来源解析 | 同路径、同版本的实际已读字节，无缺口且重叠一致的片段可拼接 | 未读部分、旧版本或其他运行的材料已获当前读取资格 |

算术绑定区分 `source_value`、`test_input`、`proposed_constant`。原文值由实际读取的数字 token 或 JSONPointer 提取；样本不能覆盖来源值。没有隐式浮点容差。原文纯算术还须有完整行边界才可确认前提；复杂代码翻译、分支和修正建议前提进入风险复核。

JSON 必须是所选区间中的一个完整标准对象，严格消费到末尾，拒绝转义后重复键、隐式转换、注释和尾逗号。`null / false / 0 / ""` 均不是缺失。合法片段不能证明未选择的对象范围。读取回执新增可选 `line_boundary` 元数据；旧记录缺失时保持未知。

单草稿最多 64 项检查，每项最多 16 个数值样本；表达式最多 128 节点、深度 16；JSON 主体最多 64 KiB、深度 32；数字字面量最多 128 字符，中间有理数分子／分母最多 4096 位。超过限制不会执行其他解释器兜底。单份受限质量材料另设16 MiB保存及读取边界，超限阻断，不静默裁掉检查。

每个检查同时保存 `result` 和 `premise_result`，并绑定检查器版本、来源版本及区间、输入和实际结果：

- `pass`：指定关系成立。
- `fail`：有可计算反例。
- `error`：检查输入、类型、除零或资源限制问题，不能据此认定业务代码有缺陷。
- `not_run`：来源不足、陈旧或语义不受支持。

## 复核、记忆与预算

推断、建议、跨文档比较、迁移、否定判断及前提未获确认的核心项进入风险复核，全部风险项须进入复核包。纯逐字材料事实及前提明确的局部核验可跳过模型复核。跳过不等于独立语义验收通过。

复核使用父任务的同一模型与渠道，无工具。`quality_review` 和 `quality_revision` 通过现有 Provider、计费、请求诊断及观测链路发出独立短请求，不重新注入普通全量历史。必要包超过硬上下文上限时直接阻断，不裁掉关键发现。复核空响应、坏 JSON 或工具调用不追加修复请求。作者修订只用已有证据，缺少新证据的内容降为待核实。

复核和作者修订各占一轮及一次模型准入；准入与扣数在同一锁、同一持久事件中完成。核验、最终报告发布分别计正常工具尝试。没有新的额度、固定预留或自动重试；预算、取消和关键存储失败沿用原优先级。

质量模式的泛摘要不能单独授予关键原文折叠资格。笔记投影须保留有效发现的完整依赖、短摘录、数字、默认值和例外；未解决项、暂缓项及被省略的笔记对应原文继续保留。仍使用 16 KiB 笔记投影、96 KiB 软目标和既有硬上限。原 Session、工具配对、Responses 不透明项及未知原始项保持原行为。质量模型候选的持久回执仅保存`content/tool_calls`，非法工具批次和修订拒绝分支也使用相同白名单，不新增保存完整`ResponseItems`、推理块或其他不透明项。处理声明与有效短引文不能证明模型没有遗漏尚未记录的数字、默认值或例外，这一限制由外部语义量表单独评估。

## 状态、证据与恢复

普通任务的 `taskState.Version` 仍为 1；质量任务使用 2，并必须含有效 `TaskSpec.Quality / QualityState`。任务事件及快照外层格式仍为 1，计时 payload 与任务状态版本匹配。质量配置版本、质量状态版本和读取记忆存储版本各自为 1。旧二进制会拒绝状态版本 2，不能忽略质量字段后恢复执行。

`QualityState` 保存草稿身份／摘要、来源版本、范围依赖、阶段准入／结果、材料及读取证据摘要、冻结发布材料。普通读取资格不因恢复而复活；已完成票据的专用读取还须匹配登记的运行、Agent、证据摘要、当前权限、来源及范围版本。受限材料读取复核摘要，不从自然语言猜测身份或阶段。

| 已记录情况 | 行为 |
|---|---|
| `checking`，或复核／修订为 `admitted` 且无完成回执 | `quality_outcome_unknown`，不再次请求 |
| 完成票据且来源、权限、范围仍匹配 | 可继续已授权交付，不重新核验草稿或复核 |
| 来源／产物已变化 | 阻断或沿用报告陈旧语义，保留已经确认的文件效果，不自动重写 |
| 关键证据、事件持久化失败或材料摘要不符 | `FAILED/storage_error` |

质量阶段包含 `exploring / checking / checked / ready / blocked / published / stale`；模型阶段分别记录 `not_run / admitted / completed / invalid / failed / skipped`。`RunResult.Quality` 只交付质量摘要、分项阶段和未解决项，不冒充外部语义评分。

核心全部不可用为 `BLOCKED/quality_not_ready/2`；协议无效为 `quality_contract_invalid`；已准入结果未确认为 `quality_outcome_unknown`。合规分析可返回 `ANSWERED/0`，合规报告仍为 `NEEDS_VERIFICATION/2`。报告的 `semantic_result` 初始且仍为 `not_run`，内部核验不改为 `VERIFIED`。

CLI、飞书及观测台展示相同质量分项。全局观测只保存阶段、计数、原因及指纹。观测台对质量任务不开放内部 task artifacts，包括旧映射 ID；最终文件仍通过可信产物回执访问。详细计算、草稿及复核正文留在受限任务目录，遵循现有证据权限和手动清理规则。

## 构建、重启与验证

```bash
go build -o claw ./cmd/claw
go build -o claw-monitor ./cmd/claw-monitor
```

CLI 和观测台应同步更新。已运行的 REPL／`go run`／监测进程不会因为替换二进制自动更新：等正在执行的任务退出后，关闭旧进程并用新程序启动。不要把旧观测台无法解释的新状态显示为零用量；新 Inspection 读取器支持两版状态。任务历史不会重写。

离线验证包括项目测试、race、构建，既有真实评测／写入／覆盖／笔记 selfcheck，以及独立 `scripts/quality_first_eval/run.py selfcheck`。实际执行日志和通过情况由本轮验收记录单独保存，本说明不预先宣称全部通过。

新 `quality_first_v1` 实验独立于历史 profile。最多 `baseline-report-1 → candidate-report-1` 两样本；双方相同报告入口、冻结来源、完整阅读要求、模型和预算，仅候选开启质量模式。质量先评，包括重要遗漏和错误修正建议；main、review、revision 的实际调用、Token、字节、耗时及未知费用随后分别报告。基线低分不阻止候选；合法业务失败保留消耗，基础设施／协议错误、取消、禁止路径变更或结束未确认停止批次，不自动重试。

本地检查和同模型复核仍可能漏掉重要问题或共同产生错误。真实一对实验只支持该任务的小样本判断；未达到质量目标时保持显式入口，不默认推广，也不以提前失败或全部降为待核实宣称降耗。

本地检查针对模型显式登记的 `QualityCheck`，不会从任意自由文字中自动提取全部数字命题，也不能证明没有遗漏待检查的公式。风险复核只依据短包中的材料，不等同于重新通读整个资料库。外部质量评审须继续检查未登记的重要问题、错而未检出的建议及修订新引入的错误。
