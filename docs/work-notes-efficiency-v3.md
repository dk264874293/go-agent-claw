# 工作笔记采纳与汇总效率 v3

本轮针对任务 `35d1dab88e64b1a75c07f72fe194c3e2`：资料已完整读取，但工作笔记未被采用，旧原文持续进入请求；前3轮还先列了6次目录再发现文件。任务35是症状参考，不能替代同批基线。

## 默认行为与兼容

新任务默认保存 `read_context_version=2`。恢复沿用原任务的0/1/2版本，不自动升级；读取记忆存储版本仍为1。v2普通任务通过现有工具的可选参数附带短笔记，不增加记笔记工具或独立模型请求。缺失或无效笔记不阻断业务工具，也不获得折叠资格。

CLI、Bench及飞书共用引擎的新任务默认值，无需新增启动参数。严格分析仍显式 `-analysis`，证据报告仍显式 `-report`；二者继续原结构化报告契约。普通终答及业务JSON保持原格式，不因为没有引用而新增任务阻断。

## 工具载体

仅普通v2任务的 `read_file/read_lines/write_file/edit_file` 请求Schema提供可选、最多8KiB的 `_work_notes`。它不是文件正文；Bash、目录、搜索、委派及 `write_report` 不增加该字段。

```json
{
  "path": "下一份资料.md",
  "line_numbers": true,
  "_work_notes": {
    "schema_version": 1,
    "findings": [],
    "processed_reads": ["E1"],
    "summaries": {"E1": "填写实际已读主题、版本、关键事实与适用条件，不用‘已读’代替内容"},
    "deferred_reads": [{"evidence_id": "E2", "reason": "尚需对照另一版本的默认行为"}]
  }
}
```

示例ID必须替换为当前已经交付的真实证据。模型在本响应第一个适用工具调用附带一次增量；不累计重发，不为补笔记增加一轮。已有 `work_notes` 文字信封继续兼容；同响应优先消费有效工具载体，没有有效载体才尝试文字信封。相同内容去重，同批冲突保留先接受的有效项。

处理顺序为：完整批次工具身份校验 → 笔记校验及持久化 → 生成执行副本 → 原有准入和执行。执行副本只剥离最外层保留字段，业务正文中的同名键不变。动作指纹、重复读取判断、审批、Pending、回执复用及Handler均使用执行副本。

无效引用、null、结构错误或超限载体返回简短原因，原文继续保留；关键记录存储失败仍为 `FAILED/storage_error`，不能当作可忽略的笔记错误。无法可靠解析的业务参数交原有工具校验，不通过笔记机制修复参数。

## 安全投影与失效

后续请求副本可移除已经消费并绑定调用身份及参数摘要的 `_work_notes`，原Session消息和历史记录不改写。Chat、Anthropic与Responses一致处理；Responses只修改匹配 `function_call.arguments` 中的保留字段，业务参数、调用ID、顺序、opaque reasoning及未知项保持。无法唯一匹配时原样保留并统计未清理字节。

载体已消费只允许清理元数据，**不代表其笔记有效，更不授予原文折叠资格**。正文折叠仍须同时满足：

1. 当前运行、Agent、权限、来源版本有效。
2. 原文完整进入过一次成功模型请求。
3. 模型明确声明处理，且当前投影仍有有效发现或摘要。
4. 不属于最新完整工具批次，也没有该证据的有效暂缓声明。

后续有效处理声明才能解除暂缓。文件写入、未知效果、实际Bash执行及来源变化沿用既有失效规则；恢复后的历史读取不会自动成为当前依据。96KiB软目标、16KiB笔记投影与上下文硬上限均不提高，不能安全压缩时保留原文或沿用原有阻断出口。

摘要与引用通过只证明结构、位置及来源可用，不证明模型没有遗漏或结论正确。

## 发现与汇总质量

已知文件类型、需要跨目录汇总时，从目标根直接递归 `find_files`；不需要先逐层列目录。已有发现只提供实际取得的清单身份及选择条件，不隐式扫描，不保证目录成员以后不变。截断、需要刷新成员或目录结构本身是任务对象时仍可正常探索。

普通汇总保留主线并指出明显矛盾；重要结论就地引用文件与行号，文末索引不代替依据。数值必须区分原文标注、静态推导和实际执行；被引用的计算需要核对输入、默认值、分支、公式与总和，不自动执行材料内脚本。

有限回归包含：原文84.5/39.5与固定输入静态推导97.5/29.5的区别、缺score默认5→12.5、非空检查不等于ID/URL/枚举合法性，以及既有版本演进、Hook未实测、已有测试命令和缺页反例。准确转述原文不是捏造数字；遗漏其内部矛盾需单独评审。未知表述不由有限oracle冒充通用语义判断。

## 验证与真实对照

源码及二进制先冻结，包含现有未提交源码与完整冻结夹具，排除凭据、任务运行数据和构建产物。分批差异与日志保存在本轮 `.claw/repair-checkpoints/work-notes-v3-*` 检查点。

基础检查为Go全包测试、内部Race、模块包构建，以及real_eval、write_efficiency_eval、coverage_efficiency_eval和work_notes_eval的离线selfcheck。脚本Provider和本地HTTP服务验证载体、业务指纹、完整工具配对、原历史不变、三协议实际编码与存储/恢复边界。

真实实验仅由 `scripts/work_notes_eval/run.py run-one` 显式启动：固定 `deepseek-v4.1-flash-1017`、项目 `.env`、同一冻结资料及题面、8000读取档、60模型/120工具/30轮/600秒/300000上下文字节。每样本独立新工作区与会话，观测和metadata诊断也按样本隔离，不新增正文授权。

题面只给根目录、全部Markdown要求、指定产物与精简偏好；不泄露文件清单和数量，不启用analysis/report/require-full-read。私有manifest只供验收器核对。

顺序为旧→新、新→旧、旧→新，最多3对6样本及360次模型准入。先完成并评审一对；完整覆盖、仅新增指定产物、原文未改、`NEEDS_VERIFICATION/2`、无未决动作且候选质量≥8/10、不低于基线、零重大事实错误、候选≤12模型/40工具，才扩展。基础设施失败或首对未过门槛即停止，不重试、不另补样本。

最终目标为候选模型中位数≤10、工具中位数≤26、总输入输出Token中位数较同批基线降低至少30%。另报笔记采纳、折叠字节、发现轮次、生成与总耗时；失败消耗全部保留，费用未知为null。小样本不证明稳定泛化，历史任务差异不算受控收益。

评审使用匿名产物和固定五项量表，保存评审者及方式；实施会话的静态评审不冒充独立人类验收。断言绑定产物SHA、实际UTF-8输出区间与文本，以及来源SHA/行号/摘录；遗漏绑定量表项而非伪造输出片段。未评审为not_run。

全局观测只记录计数、稳定原因码、载体/清理/折叠字节等白名单元数据，不保存笔记正文，也不改变任务终态和调用预算。
