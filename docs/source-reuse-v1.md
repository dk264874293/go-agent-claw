# 普通任务来源复用与局部核对 v1

新普通任务使用 `read_context_version=3`，严格 `-analysis/-report/-quality` 继续默认策略2。普通任务状态仍1，读取记忆存储仍1。历史策略0/1/2不升级，恢复不获得旧材料的当前资格。CLI、飞书和Bench统一由引擎应用默认值，不增加启动开关。

## 来源视图与折叠

`read_evidence` 对有成功原始读取记录的文件材料返回结构化视图：本次新EID、动作、消费者、源文件完整版本、实际字节及行范围。`ReadReceipt.source_view` 保存原EID、原动作、原材料和材料内切片。视图不重复保存原文字节，不继承原E的交付和processed资格，直接指向最初读取，不生成视图链。

`offset` 仍是材料内字节，`limit` 为1–4000，省略或0默认4000。当前源视图默认显示绝对行号，实际消费同时受编号显示预算约束；下一页使用返回的next_offset。半行、UTF-8及摘录仍受原引用契约校验。普通工具输出、搜索和子报告不因看起来像源码而升级为来源。

重复判断跨read_file/read_lines/read_evidence按实际来源区间生效。当前Agent已有原文或有效笔记可用时，无目的精确重复返回REJECTED/NONE/duplicate_read，仍扣工具尝试。必要核对使用review.target_id和具体question；不同区间合法重叠不因新增覆盖为零而直接拒绝。父首次核对已交接子材料生成父的新证据，不继承子资格。

策略3的read_evidence支持可选_work_notes，沿用剥离、软拒收及原Session不改的机制。成功完整进入模型请求、明确处理、当前投影仍有有效笔记且非最新批次，才允许折叠。未处理、暂缓、投影省略和失效材料继续保留。历史、文件变化、未知写入、Bash进入Handler后的旧材料不能恢复当前依据，即使SHA相同也须重新读取工作区。

## 局部核对

新普通策略3提供只读check_evidence，输入checks数组。每项包含kind（arithmetic/json）、subject（evidence_ids及成对行范围或字节范围）、expression/bindings/cases或assertions。ID由引擎生成，不要求质量草稿或结构化最终报告。

来源必须当前运行、权限有效并已完整交付；同路径同版本、无缺口且重叠一致的已读页面可拼接。不自动扫描、补页、猜选Markdown对象或执行资料脚本。JSON必须明确选定完整对象，缺失与null/false/0/空字符串不同。可选label/短锚点只描述位置，不证明业务对象分类正确。

每调用最多8项、请求最多64KiB；每项最多16样本/断言/绑定，沿用JSON主体64KiB/深度32、表达式128节点/深度16、数值字面量128字符/中间结果4096位。精确有理数检查不冒充复杂代码分支或默认值语义执行。

结果分pass/fail/error/not_run，并报告前提、具体来源、主体摘要、实际值和证明范围。得到反例仍是工具正常完成，不自动重试。普通任务不因检查失败被程序阻止交付，检查通过不升级语义或运行验收。

核对正常扣共享工具额度，可与独立读取同批；同批写入/Bash返回未执行的check_result_pending，下一正常响应再使用观察。没有专用模型阶段，实际轨迹可能因观察核对结果增加正常响应。

完整回执先登记受限材料ID，再保存材料，最后更新完成。prepared未完成显示not_run/结果未确认，恢复不自动重算；事件及关键材料失败沿用storage_error。RunResult.local_checks和Inspection保存动作当时摘要，CLI、飞书和观测台分别展示局部核对、覆盖及引擎验收。观测台不枚举或提供完整核对回执。策略3在索引落后时也只开放已提交来源材料及可信文件产物；未分类的通用材料保留CLI的read_evidence及受限任务记录入口，不在网页猜测开放，防止prepared提交与目录枚举之间的竞态泄露。

## 观测、交付与运行

全局source_view_created/source_view_historical/local_check_completed仅保存身份、版本、区间、字节数、结果及主体摘要，不写原文、表达式、笔记或完整响应。Schema、实际编码请求字节、上下文材料字节、累计折叠和Token分别统计；缺失基线指标未知，费用未知null。

覆盖完整不自动解除暂缓，也不证明结论成立。笔记优先保存对象、关键值、默认值、版本条件、精确引用和未解决项。已有确认产物时引导定向核查及交付，不因一次写入强制停止必要编辑和验证。可信链接继续由文件效果回执生成。

构建CLI及观测台后重启对应进程，新任务才采用新策略：

```bash
go build -o claw ./cmd/claw
go build -o claw-monitor ./cmd/claw-monitor
```

旧运行和恢复任务保持原策略。本轮离线检查后使用独立source_reuse_v1普通双样本profile，旧实验不改。运行入口为`python3 scripts/source_reuse_eval/run.py --help`；最多一对120模型准入，质量先判，机制效果和成本分别报告。≤12模型/40工具及30%Token下降仅为观察目标，一对样本不支持泛化结论。
