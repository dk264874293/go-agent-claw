# 阶段 2 开发 spec：权限与执行隔离

状态：本地实现与自动化验收完成；原生 Linux 主机平台验收待执行。对应开发计划 S2-01 至 S2-07，以 M1–M3 无网络回归为基线。

## 目标与实施顺序

先固化 CLI 真实进程与本地伪网关的综合测试。随后实现权限、根目录文件操作和只读探索工具；在 Docker Desktop 的 Linux 容器内完成隔离原型后实现 Executor 与本地审批。目标 Linux 主机的运行验收单独记录，交叉编译不代替运行验证。

## 权限与审批

- 能力为工作区读取、工作区写入、进程执行、网络和委派。每个工具显式声明能力，未声明的工具默认拒绝；Registry 在所有中间件之前检查权限。
- 运行权限由入口装配，工具结果、文件内容和模型参数不能扩大权限。子任务上下文只允许读取，且不装配通用 Shell 或递归委派。
- 写入、执行和网络能力必须有可信审批来源。审批绑定 RunID、SessionID、工具、原始参数 SHA-256、审批主体和期限，只用于该次调用；参数变更、过期、拒绝、取消与缺失审批来源均拒绝执行。
- 首个审批来源是本地终端用户，独立使用 `/dev/tty`，避免 REPL 输入被审批抢读；等待响应工具 context。无控制终端、显式 deny 和飞书入口拒绝有副作用操作，旧飞书口令不作为新权限层的授权凭据。

## 文件与只读探索

- 新增 `internal/workspace`，路径只接受工作区相对路径，拒绝绝对路径与 `..`，实际操作通过 `os.Root` 完成。文件读取非阻塞打开后检查常规文件类型。
- 写入使用根目录内临时文件和根目录约束的重命名；拒绝直接覆盖符号链接与特殊文件，编辑有界读取后复用相同写入路径。外部符号链接和链接替换竞争不得修改工作区外文件。
- 文件工具不提供宿主机沙箱；工作区内硬链接、挂载点和其他拥有宿主权限的程序仍需要运行环境治理。临时文件替换避免直接修改原文件的硬链接目标。
- 新增 `list_files` 和字面量 `search_text`，目录、文件大小、遍历数量、深度、匹配数量和输出都有上限，响应取消，搜索跳过遍历中遇到的符号链接，并拒绝打开末级符号链接；中间路径按 os.Root 的根目录约束解析。工具不调用宿主 Shell。

## 容器执行

- Executor 只支持本机 Linux Docker Engine，macOS 通过 Docker Desktop Linux VM 验证。运行镜像必须已安装，运行时解析为不可变镜像 ID；不自动拉取镜像或回退宿主 Shell。
- 使用非 root 用户、只读根文件系统、去掉所有 capabilities、no-new-privileges、CPU/内存/PID 限额、受限 tmpfs 和显式网络策略。只挂载指定工作区，不挂载 Docker 控制接口或宿主其他目录。
- 容器挂载的工作区包含其中所有可访问文件，因此 Shell 工作区应是操作者指定且不含密钥的工作目录；不把绑定挂载描述为秘密过滤器或完整主机防护。
- 容器不继承应用进程环境变量，只提供固定 PATH、HOME、LANG；Docker 客户端也只保留连接所需的允许列表。模型不能调整镜像、挂载、用户、配额或网络配置。
- context 取消及正常退出都强制删除本次容器；清理失败作为独立执行错误报告。输出持续排空、保留前 8000 字节。

## 外部文本

核心提示词明确文件、项目指南、Skills 和工具输出的来源与可信级别。工具数据不提供审批或权限；即使文本要求越权，Registry 仍独立拒绝。文本标记不作为安全保证，验收以执行结果为准。

## 验收

1. 固化正常 CLI 工具任务、预算拒绝、REPL 多 Run 的真实进程测试，伪网关只监听本机，不读取项目 `.env`。
2. 权限拒绝发生在中间件和工具之前；只读子任务不能执行写入、Shell、网络或委派。
3. 文件越界、符号链接、特殊文件、链接替换竞争被拒绝或安全失败，工作区外测试文件不改变。
4. 受限搜索/浏览成功、非法参数、底层失败、越界、输出上限及取消测试通过。
5. 审批绑定、过期、变参、主体、取消和非交互拒绝测试通过。
6. 本地容器验证非 root、网络禁用、宿主测试秘密不可见、配额、取消回收和后端不可用；运行容器测试须显式 `CLAW_TEST_DOCKER=1`，普通单测不依赖 Docker。
7. `go test ./cmd/... ./internal/...`、相关 race、vet、build 通过，真实 LLM/飞书调用不在本次范围。
