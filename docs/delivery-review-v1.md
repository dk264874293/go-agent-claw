# 普通任务交付前处理 v1

此入口给普通任务一次按需处理已记录待办的机会，默认关闭。它不增加独立评审Agent、不提高权限或共享预算，不把处理声明当作语义或运行验收；也不能保证发现尚未登记的重要问题。

## 启动与接口

```bash
# 普通修改任务：原有读写工具和自由Markdown/业务JSON保持
./claw -mode workspace -delivery-review on -prompt "阅读资料并生成汇总"

# 普通只读回答
./claw -mode readonly -delivery-review on -prompt "分析资料的适用范围与风险"

# 需要局部确定性核对时单独开启；不会由delivery-review隐式打开
./claw -mode workspace -delivery-review on -local-checks on -prompt "阅读并核对资料中的计算"

# 恢复只使用持久设置，不能重复传-delivery-review，连off也拒绝
./claw -resume 任务ID
```

CLI的`-delivery-review off|on`是字符串开关，默认off，不能写true/false。Engine使用可选`TaskSpec.DeliveryReview=&DeliveryReviewSpec{Version:1}`；版本必须显式为1，nil保持关闭。仅支持普通`readonly + answer`或`workspace + change`，不能组合analysis、report、quality、plan、额外thinking或trusted入口。CLI在创建Provider前校验，引擎仍重复校验。

新任务使用taskState版本3，普通关闭任务仍版本1，质量任务仍版本2。读取记忆存储格式保持1，读取策略仍为2或显式ReadFeatures的4。历史任务不升级；旧二进制必须拒绝版本3恢复。恢复沿原配置，Engine不能给旧任务开启或改变本策略，CLI拒绝任何显式新开关。

ReadFeatures三项继续独立：本入口不会隐式开启source_views、local_checks或claim_focus；原注册表的工具定义不变。局部核对关闭时，模型不能调用check_evidence；处理响应只可使用当前可见、已获权限的工具。

Bench提供同名全局off/on开关，`TestCase.DeliveryReview *bool`区分nil继承、false显式覆盖关闭、true开启。新增可选`Mode/Kind`为普通只读回答或普通工作区修改配置入口，不能与ValidateScript混用；旧Trusted/ValidateScript用例保持原义。普通workspace+change的NEEDS_VERIFICATION仅判为达到引擎交付预期，不冒充运行或语义验收。飞书本轮不新增启动配置，仅复用统一终报。

## 文档处置、等待范围与一次处理

沿用现有工具顶层`_work_notes`软载体，在启用任务中增加可选`source_reviews`：

```json
{
  "_work_notes": {
    "schema_version": 1,
    "source_reviews": [
      {
        "evidence_ids": ["E1"],
        "finding_ids": ["F1"],
        "disposition": "addressed",
        "reason": "相关发现已记录对象及适用条件"
      }
    ]
  }
}
```

示例ID须替换为当前真实材料。处置可为`addressed / not_relevant / unverified`，必须说明理由；addressed须关联有效发现，不把无依据的processed或泛摘要直接当作重要问题已经处理。引擎绑定Agent、运行、路径、完整版本及发现摘要；身份、引用和状态通过只说明声明有来源，不证明声明语义正确。已有findings、summaries、processed_reads、暂缓及载体剥离机制继续复用，不新增记笔记工具。

读取已processed不代表文档处置已完成。显式开启本模式时，即使没有新的读取候选，仍可在既有适用工具的`_work_notes`中增量提交当前有效来源的发现、`source_reviews`及核对处置；没有有效增量时省略，不为登记状态增加工具或模型请求。默认关闭任务保持原提示。

暂缓读取可在`deferred_reads`中附`wait_for:{byte_start,byte_end}`，为源文件绝对字节的半开区间，不能超过文件总长度。必须锚定本人当前已交付证据；后续同源片段成功进入模型请求，等待范围齐备时只变为`ready_to_resolve`。不会自动撤销暂缓、标processed、授予折叠或清除未知。文件变化、写入效果未知、Bash实际执行和恢复继续撤销当前复用资格；历史材料不自动成为新依据。

处理时序为：

```text
正常读取及有来源的工作笔记
→ 接收本响应的有效处置声明
→ 首个可准入的write_file/edit_file批次，或正常非空最终答复边界
→ 检查已记录的ready、未处置来源及未解决核对
→ 有待办且额度允许：整批退回一次，或暂存候选终答
→ 根Agent下一普通请求集中处理
→ 后续按原规则自由交付，有效部分与待核实项并列
```

无待办时记录not_needed，不添加模型请求，也不消耗处理机会；先创建无来源占位文件后再读取资料，仍可在真正出现待办时触发。首次有待办的处理决策后不再重置，预算不足也不通过恢复获得新机会。退回前在同一锁及持久事件内登记一次性身份并扣一轮、一次模型；下一根请求只消费这张票据，不再次扣数。退回批中的全部新调用均未进入Handler，不创建Pending、不自动重放，逐调用保留REJECTED/NONE及匹配结果，尝试仍扣工具额度。`delivery_review_required`是调度回执，不触发普通错误自愈、连续失败或只读失败收尾。

已确认历史回执、同批核对与写入本来就不兼容、权限或参数无法准入的写调用，不用本入口伪造新的未执行效果。额度须覆盖退回尝试并让既有主循环仍可进入下一模型请求；不足时不强行退回，不延长预算，沿现有执行或停止规则处理。取消、预算、关键存储错误及未知效果保持既有优先级。

聚焦请求复用原根Agent、普通请求构建、读取交付标记及现有工具，不是独立模型评审。仍可必要读取、核对和写入；一次强制退回不等于整个任务总模型数最多只增加1，因为工具观察仍需后续正常响应。没有额外摘要、格式修复或自动补读调用。

## 重要命题定向处理增量（2026-11-08）

开启本入口后，4KiB目录同时投影当前Agent、本运行、版本和权限仍有效的发现：结论、完整依赖、精确引文、适用条件及限制。推断/建议优先安排核对，这只是顺序，不是程序计算的语义风险等级。检查失败、来源不足和待重新处理事项优先于普通文档计数；超大条目整体省略并显式计数，不截断JSON、引文或依赖，且不阻塞后续可容纳的条目。完整笔记和未处理原文仍走原有16KiB/96KiB投影及硬上限，不因目录省略新增折叠资格。

定向提示要求先处理会改变结论的数值、默认值、字段存在/非空/类型/合法性、版本迁移和跨文档两端条件。只核对任务将采用的重要命题，不要求每篇材料编造问题。已有检查回执提供ID、结果、前提、失败原因及受限材料引用；数学通过不证明代码前提成立。`check_evidence`仅在独立启用local_checks时建议使用，来源变量必须给出`source_value + source + pointer`等明确绑定，不从subject隐式继承来源。工具未开启时不提示调用隐藏工具，不执行资料脚本。

核对结果应进入原有写入或终答：修正、限定或明确待核实。检查后确实无需改动时允许保留正文；只增加source_reviews不证明修正已发生。`fail/error/not_run`检查即使没有解析出Sources，仍作为本Agent本运行待办保留。全部文档声明不相关而没有有效发现时仍提供一次处理机会；允许解释确无相关材料，不新增语义发布阻断，也不追加第二次强制退回。

`DeliveryReviewState`和`RunResult.DeliveryReview`新增可选`content_comparisons`，不改变任务版本3或读取记忆格式1：

```text
kind: file / answer
path: 文件候选的工作区相对路径（终答为空）
candidate_sha256: 处理前候选正文摘要
confirmed_sha256: 确认正文摘要，可空
action_id: 文件确认动作，可空
status: not_compared / changed / unchanged / unknown
```

完整write_file候选与随后本运行的新确认文件回执比较；无工具候选与正常最终答复的原始字节比较，不改写业务JSON或FinalText。同批同路径多份候选、只有edit_file意图、无确认回执时不猜测比较结果。未知效果保留unknown；恢复不使用新动作覆盖旧运行比较，历史回执复用不冒充新发布。候选摘要不可换，比较元数据随现有准入、动作结果和finished事件持久化，不新增模型/工具调用或工作区扫描。旧记录缺少字段时不补算，也不重写历史任务。

CLI、飞书统一终报与观测台显示“正文相同/不同/未确认”，只说明动作确认时的字节，不代表语义改善或文件当前状态。全局观测只增加changed/unchanged/unconfirmed计数，不保存候选正文、引文或笔记。不得把正文不同、文档声明数增加或检查pass当作质量验收通过。

离线新增动态数学样例，脚本从真实核对回执提取计算结果，分别处理反例与通过分支，再将限定结论写入真实产物；并检查预算、确认摘要和零提前写入。另覆盖无来源失败、无发现触发、超大命题省略、失效、自由JSON、未知效果、历史运行隔离及展示脱敏。生产提示不包含课程私有答案。离线通过只证明机制可用，不证明真实模型会主动核对或报告语义质量已提升。本轮不启动付费对照。

只读最终答复不要求封装JSON或为登记状态调用无用工具。一次响应已记录只表示机会已使用；没有有效结构化处置的事项继续保留为未解决，不能从自由文字猜测全部解决。`FinalText`和业务JSON原文不改，摘要单独交付。

## 状态、交付与隐私

### 核对参数与增量笔记修复（0251症状，2026-11-08）

命名算术变量必须在bindings显式声明身份；只给cases[].inputs不能满足契约。Schema增加完整的小型数学样本，分别说明source_value的来源要求、test_input的样本值和proposed_constant的固定值。引擎不猜测变量身份，不把静态推导值自动提升成原文值，不放宽来源、范围或权限。

确定性检查回执新增可选diagnostic，包含机器码、完整变量名、有界省略数量和纠正提示。binding_identity_missing、binding_kind_invalid、sample_binding_conflict分别表示缺失身份、身份枚举错误和样本试图覆盖非测试绑定。分类来自检查器内的类型化错误，不解析中文错误文本。错误仍为正常完成的检查回执error，不自动重试；数学反例保持fail，来源不足保持not_run。摘要的ReasonCode和全局观测只记录机器码；输入、变量与完整提示仍在受限核对材料及正常工具响应中。旧记录没有diagnostic时保持旧分类，不补造诊断。

读取候选目录增加suggested_increment（最多4个当前有效、当前消费者的证据ID）、suggested_note_bytes=2048和carrier_limit_bytes=8192。先选先前交付仍未处理的来源，再选本请求完整提供的来源；建议不授予实际交付、处理或折叠资格。模型可在已有适用工具响应中提交少量有事实和条件的摘要，不要求本次处理全部候选，也不等到写报告才集中提交。2KiB和4份是软建议，8KiB硬上限保持；重要数字、默认值和例外不能为缩短而丢弃。超限仍整份软拒收，但回执明确给出上限及分批纠正提示，不会部分接受或自动补调用。未处理、暂缓、投影省略及版本失效的原文继续保留。

显式交付前处理对长篇Markdown增加source_locations_absent提示：当前有已交付有效来源、围栏外正文不少于1024字节，但未识别任何已读文件的完整相对路径:行号时，利用已有的一次处理机会提示补充就地位置。它仅检测完全缺少受支持的位置格式，不证明每条引用有效或每个重要结论都有依据；已有其他引用格式时也只作提醒。短答、业务JSON和围栏代码不套用此规则，不自动补写或改写正文。比较仍要求模型引用两端并说明默认值、版本、非空与合法性等条件；不能只补一条“核对失败”声明。

本增量不改TaskSpec策略版本、读取记忆版本、权限、预算或恢复票据，也没有新增模型阶段、自动执行或透明缓存。离线脚本从实际diagnostic生成明确测试身份后重新核对，并验证正常预算、反例与前提边界；小笔记使旧正文获得折叠资格，未处理正文仍保留。真实模型是否采纳、质量和Token是否改善，需要后续真实任务验证，本修复不新增付费运行。

### 分项解释、可定位引用与目录差异增量（2026-11-08）

本增量继续使用显式开关及已有的一次处理票据，没有新模型阶段，也不新增语义发布门禁：

- 算术回执区分结果、前提和分项解释。策略4的局部核对输出增加完整来源路径/行号/字节范围、规范公式及样本实际值；按完整条目省略并计数，仍不超过8000字节。即使给定算术与原文纯算式均通过，分项字段、对象、默认和截断分支也不因此通过，另以interpretation_result=not_run说明。完整检查仍保存在受限材料。cases[].expected必须放在样本内，不接受顶层expected。
- 开启交付前处理时，提示使用证据表的完整citation_location。P/E/F只作内部短身份；不得按编号猜文件。候选Markdown中的P9:10等未展开引用产生citation_alias_unresolved提示，明确的“P9 = 已读文件路径”映射可识别；围栏代码内的同形文字跳过。没有自动推断别名、更改正文或给自由文本引用授予精确验证。
- 目录树与当前本人、本运行已成功交付且仍有效的原文路径字面量比对。仅对唯一匹配的缺失前缀提出source_path_difference，并提供原文路径和行号；歧义时不猜。它提醒区分原文布局和建议布局，不判断哪种布局能运行，也不查磁盘实际目录。当前只识别常见ASCII相对路径字面量与树形符号，不是通用Markdown或代码分析器。

机械检查最多使用128份当前读取和256个位置/路径条目，正文上限256KiB；每次回执最多8条提示、编码后3000字节，省略可见。no_issue_found只表示这些有限规则没有发现提示，不能表示引用、语义或运行验收通过。已有目标路径超过512字节或正文超限时标为not_run；局部edit_file没有整份正文时也标未完成全文检查，不自动重新读取文件。

候选提示复用已有一次退回机会，在聚焦目录的candidate_issues列出，明确它是原候选问题。确认write_file后，结构化ContentReview随原action_result保存；同路径多次写入按效果账本动作顺序选最后一次检查，不逐事件累加，不将局部编辑当作全文修正。未解决提示进入既有DeliveryReview摘要，正常最终答复也重新检查；忽略提示仍可自由交付，提示不会变成工具错误、自愈重试或第二次强制退回。恢复不把旧回执升级为当前检查。新字段可选，不改任务版本3、读取策略或存储格式，不补写历史记录。

CLI、飞书和观测台沿用未解决清单展示；FinalText、业务JSON和文件正文不改写。提示仅含行号、路径及来源身份，不新增正文/私密思维留存或全局观测正文；文件回执继续只说明动作当时的确认。离线自适应脚本从实际读取及差异回执形成修订；它证明反馈链路可用，不能证明真实模型报告质量已经提升。本增量没有发起付费模型运行。

`DeliveryReviewState`保存一次性准入、原RunID、轮次/模型票据消费、阶段、触发理由、受限候选材料ID及摘要。阶段为`not_run / not_needed / admitted / completed / failed / outcome_unknown`，准入次数只能0或1。准入后中断或请求结果缺失，恢复显示未知，不重发该处理请求、不重置一次机会；后续普通运行仍受原有恢复和预算约束。

`RunResult.DeliveryReview`与只读Inspection交付状态、准入次数、来源运行、文档处置分布、ready数量、未解决清单及证据/发现/检查ID。CLI、飞书及观测台使用相同语义，均不能展示为“质量通过”。未解决项有界，省略数量可见，完整任务记录保留；旧字段、FinalText及终态含义不变。

候选终答和工具意图存现有受限任务材料。全局观测只记白名单阶段、计数、原因及指纹；不保存候选正文或笔记。观测台仅开放成功动作已提交的原始来源材料和可信文件产物，未登记候选、完整核对材料以及陈旧映射ID始终失败关闭，即使读取策略2。任务文本按不可信文本渲染，不执行HTML或脚本。

## 验证、构建与运行边界

回归覆盖默认off、真实CLI on/off、显式off恢复拒绝、普通通道及不兼容组合；同批载体顺序、完整调用配对、各Provider真实编码；等待跨页、当前版本与失效；首次边界退回、无待办、额度不足、最后一次额度、存储失败、恢复不重发；自由JSON保真、终报及观测台新尝试隔离、候选泄露和已提交来源白名单。

```bash
go test ./cmd/... ./internal/...
go test -race ./internal/...
go build ./cmd/... ./internal/...
go build -o claw ./cmd/claw
go build -o claw-monitor ./cmd/claw-monitor
```

离线结果、冻结摘要及新一对真实样本由本轮验收记录单独保存；本说明不预先宣称真实质量提升。已有进程不会随构建自动更新，应等待任务退出后用匹配的新CLI与观测台重启。本轮不自动替换外部工作区二进制或重启日常服务。最多两个真实样本、同模型资料及预算；先判重要遗漏、结论和引用质量，再报告调用、实际Token及未知费用，不用调用次数较少替代质量通过。
