# 后续设计：限制计划补丁的作用范围

[机制边界](../mechanism-boundaries.md) · [调整计划](../learning-quality-plan.md)

状态：应用设计待验证，未实施。当前实现保留已完成步骤，并检查合并后的 ID、依赖和环；它仍可替换整个未完成列表，没有完整失败子图约束。

## 何时需要升级

当任务需要保护不相关的待处理步骤、保留既有外部依赖，或审批需绑定明确计划版本时，评估严格局部补丁。短只读任务仍可使用现有循环，无需为教学统一加入完整计划账本。

候选不超过三项：继续使用当前未完成列表替换并说明边界；由模型提交替换列表、确定性程序对失败子图验证；改为显式步骤增删改操作。第二项保留现有生成形态，适合作为优先实验；第三项只有补丁审计需求足够强时再考虑。

## 计划与恢复契约

1. 执行器传递稳定的失败步骤 ID，计算该步骤及其可达后继；冻结所有 Done 步骤和范围外节点。
2. 补丁不能覆盖完成节点，不能删除受影响节点已有的范围外依赖；新增节点必须接回受影响子图，并受原步骤总数与任务预算约束。
3. 合并后再次校验依赖存在、无环、稳定身份、原目标和工具范围。范围外节点内容与状态逐项比对。
4. 计划变化应重新判断审批适用性，不能沿用绑定旧版本的批准。
5. 未知 Pending 仍先核对效果；补丁不是“确认动作失败”的证据，也不能解除未知副作用阻塞。
6. 实施前明确新启用方式和持久状态版本；历史任务沿用原契约，不在恢复时自动升级。需要新字段时校验旧二进制如何失败关闭。

## 待验证场景

冻结 Done、修改不相关 TODO、删除范围外依赖、形成环、插入脱离子图节点和超出规模均有明确拒绝；合法补丁只改变受影响范围。恢复中保留已消费预算，外部效果已发生但未记 Done 时仍按动作证据核对。以当前合法计划与恢复用例为兼容基线，再增加这些反例，运行完整相关测试与内部 race。
