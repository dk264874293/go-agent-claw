# 显式分析模式 v1

分析模式用于文档和代码分析。它提供可核对的原文引用，区分材料事实、分析推断、建议和待核实项，并减少重复发送已处理正文。引用有效只证明原文位置、文件版本和实际读取依据；它不能自动证明推理正确，也不能代替独立验收。

## 启用与关闭

```bash
go run ./cmd/build-claw -o claw
./claw -dir /绝对路径/工作区 -mode readonly -analysis -prompt '分析 Markdown 文档，核对版本演进、默认行为和文档间约束'

# REPL：后续新任务使用分析模式
./claw -dir /绝对路径/工作区 -mode readonly -analysis

# 恢复沿用持久任务的分析选择
./claw -dir /绝对路径/工作区 -resume <任务ID>
```

CLI 默认 `workspace`，启用 `-analysis` 须显式指定 `-mode readonly`。`-analysis` 默认关闭，只支持 `readonly + answer`，不能同时设置验收命令。省略分析开关即可使用普通问答，任务目标包含“分析”不会自动改变模式。REPL 中 `/resume` 不受启动时分析开关覆盖。旧任务不补造笔记、精确引用或分析结果。

飞书由服务端群聊绑定显式启用，用户消息不能切换权限或分析设置：

```json
{
  "event_ledger": "/绝对路径/独立台账",
  "chats": {
    "群聊ID": {
      "work_dir": "/绝对路径/工作区",
      "allowed_users": ["成员ID"],
      "mode": "readonly",
      "analysis": true
    }
  }
}
```

Bench 的 `TestCase.Analysis: true` 使用只读回答模式，允许 `SetupScript` 初始化夹具，禁止 `ValidateScript`。此时 Bench 的“通过”仅表示任务交付了符合证据契约的报告，结论正确性需独立判定。既有修改用例继续使用可信模式和原验收脚本。显式启动 `go run ./cmd/bench` 仍可能产生模型费用。

## 读取与引用

`read_file` 有两种定位方式：

```json
{"path":"docs/rules.md","start_line":12,"end_line":24}
```

```json
{"path":"docs/rules.md","offset":0,"limit":8000,"line_numbers":true}
```

行号从 1 开始，两端包含；`start_line/end_line` 必须成对，与显式 `offset/limit` 互斥。行模式默认显示行号，可显式设置 `line_numbers`。两种方式保留 8 KiB 输出限制、版本、实际字节与行范围和续读 offset；超长行或截断时仅已交付片段构成读取依据。字节 offset 必须位于 UTF-8 字符边界，参数错误会给出纠正提示，不静默替换中文字符。按搜索返回的行号定位时使用行模式，不把行号当字节 offset。

分析模式为读取分配短证据 ID，关联动作、文件版本、实际字节范围和不可变原文材料。模型只提交 ID、行范围和短原文摘录，引擎覆盖展示路径与版本，不信任模型自报的引用状态。错行、错摘录、重复位置无法唯一定位、未读部分、版本过期或越权引用均不能支撑有效结论。搜索结果用于定位，重要结论需要实际读取原文。

## 报告与分析笔记

模型使用同一 JSON 契约提交中间笔记和最终报告，中间笔记可以与同轮工具调用一起返回，不增加独立评审、摘要或格式修复请求。示例中的证据 ID、行号和原文必须替换为实际读取结果：

```json
{
  "schema_version": 1,
  "overview_ids": ["finding-1"],
  "findings": [
    {
      "id": "finding-1",
      "kind": "fact",
      "statement": "规范将状态字段的默认值设为 draft。",
      "context": "当前读取版本的条目规范",
      "limitations": "尚未运行校验脚本验证实际行为。",
      "evidence": [
        {
          "evidence_id": "E实际证据ID",
          "start_line": 12,
          "end_line": 12,
          "quote": "status 默认值为 draft"
        }
      ]
    }
  ],
  "processed_reads": ["E实际证据ID"],
  "summaries": {
    "E实际证据ID": "本段定义状态默认值；脚本行为仍待核对。"
  },
  "unverified": ["尚未验证下游脚本是否使用相同默认值。"]
}
```

`kind` 为 `fact`、`inference`、`recommendation` 或 `unverified`。事实需要直接引用；推断和建议可通过 `depends_on` 关联有依据的发现。概览只使用 `overview_ids`，不另加无依据事实。`context` 说明版本和适用条件，`limitations` 说明结论边界，不要求记录私密思维过程。

分析提示要求先识别版本演进，核对可选字段、默认值和执行条件，跨文档判断同时引用两端材料。“未发现”须限定检查范围，未执行的运行结果或兼容性测试须列为待实测。

引擎确定性解析和校验后统一生成报告：部分引用无效时，整条相关发现降级到待核实；无有效核心结论或格式不可解析时，返回 `BLOCKED/analysis_report_invalid` 和部分报告，不自动请求模型修复。`ANSWERED` 表示合规报告已答复，不表示分析结论已验收。取消、存储失败及预算耗尽保持既有优先规则，停止时使用 `PartialReport` 交付已记录内容。

CLI、飞书使用相同终报，观测台“交付与验收”同时展示最终答复和逐条引用检查。页面以文本显示任务内容，不能执行报告中的 HTML 或脚本。源码引用指向动作当时的版本，不保证当前工作区仍是该版本。

## 上下文与用量

原始 Session 和任务记录保持完整，请求使用独立投影。路径、版本、范围在证据表中保存一份，其他位置使用证据 ID；`Progress` 在持久记录中保留，但不再将原始工具输出前缀重复注入分析请求。

旧读取正文只有在完整进入过一次成功模型请求、模型明确声明该证据已处理、并保存了有效发现或文档摘要后才允许折叠。声明“已处理”不证明材料无遗漏。最新完整工具批次、未处理正文、有效笔记、关键原文及未解决项优先保留，必要复读仍计入工具预算，不提供透明工具缓存。

请求软目标为 **96 KiB**，受现有 `-context-bytes` 硬上限约束。不能安全满足软目标时允许超出；必要材料超过硬上限时停止并交付部分记录，不自动扩大预算。文件变化撤销相关复用依据，实际执行 Bash 清空复用目录。恢复时旧笔记作为历史显示，重新取得有效读取依据后才用于当前分析。

报告分别统计请求材料体积、Provider 返回的实际输入与输出 Token、费用及未知调用。固定轨迹的字节下降不等同于真实 Token 下降，脚本 Provider 的结果也不能证明真实模型结论质量。输入 Token 降低 30% 是后续同模型、同任务、同预算对照的待验证目标；未知用量或费用保持未知。

## 保存与手动清理

结构化分析状态保存在工作区 `.claw/tasks/<任务ID>/` 的现有日志和快照中，原文证据位于该任务的 `artifacts/`，沿用现有任务存储权限及不可变材料机制。原文存储失败按关键证据失败处理，不能报告为已可靠保存。新轻量观测仍只保存脱敏结构化元数据，不增加完整模型请求、响应或私密思维日志。

旧记录缺少分析扩展字段仍可读取，不从旧工具输出猜测精确证据。关闭分析模式不会删除既有记录。首版不自动清理任务、原文证据或观测数据；如需手动清理，先确认相关 Agent、飞书和 Bench 进程均已退出，并将任务目录及其证据作为一个整体备份或删除，不单独删除仍被报告引用的材料。

## 离线验证

```bash
go test ./cmd/... ./internal/...
go test -race ./internal/...
go build ./cmd/... ./internal/...
python3 scripts/real_eval/run.py selfcheck
```

验收使用脚本 Provider 和脱敏夹具，不启动付费模型。分别验证引用机械精度、人工标注的结论正确性和请求材料体积，不能将其中一项冒充另一项。真实 Token 与结论质量改善需要后续独立的真实对照。

### 冻结轨迹材料对照

2026-11-06 在 Darwin arm64、Go 1.26.5 上使用 `analysis_quality_v1` 合成夹具回放：15 个 Markdown、87,105 源字节，固定 8 次模型请求和 30 次工具尝试。两组均执行同一份 `trajectory.json`，包含原有的重复发现与复读，模型响应由脚本产生；分析笔记随原有响应提交。

```bash
go test ./internal/engine -run TestAnalysisFrozenQualityReplayMaterialComparison -count=1 -v
```

| 统计项 | 普通请求 | 分析模式 |
| --- | ---: | ---: |
| 累计请求材料 JSON 字节 | 453,550 | 293,336 |
| 其中读取结果 Content 字节 | 286,021 | 116,590 |
| 工具 Schema JSON 字节 | 27,584 | 27,584 |
| 新增观测的有效源字节 | 未采集此分项 | 99,602 |
| 结构化分析笔记字节 | 0 | 21,168 |
| 新证据表字节 | 0 | 21,448 |
| 模型调用 / 工具尝试 | 8 / 30 | 8 / 30 |
| 实际 Token / 费用 | 未知 | 未知 |

累计材料下降约 **35.32%**，达到该固定轨迹的 30% 离线目标。总材料以实际传给脚本 Provider 的 `Messages + Tools` JSON 统一计量，不是各渠道 HTTP 报文大小或真实 Token；各分项包含不同层次的数据，不能直接相加还原总数。执行并发顺序可能使少量状态材料大小变化，回归以固定轨迹和至少 30% 降幅判定。

最终请求保留全部标注的决定性原文，六条预设事实与推断保留其引用和“未实测”边界。`oracle.json` 分别记录 V1/V2 迁移、`.get("score", 5)` 默认值和已有测试命令的原文事实、可支持推断及不能支持的断言。这证明脚本轨迹下的上下文与引用未丢失，不证明真实模型会自动得出正确结论；真实模型准确率、输入 Token 和费用改善均仍待对照验证。

> 上表35.32%为分析模式v1的历史离线结果。只读效率v2已同时优化普通请求，不能用当前两种模式的差异替代版本整体收益；真实首对结果与未达门槛的说明见 [只读效率v2](readonly-efficiency-v2.md)。
