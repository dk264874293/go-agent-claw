# 写入任务效率与证据报告 v1

本轮修复任务 `6fab055a7f97c1af02c9e5c635b7c6be` 暴露的重复阅读、引用错文件、版本/default条件遗漏及错误交付链接。执行权限、读取记忆、委派准入和报告契约分别控制，保留 ReAct 主循环和共享预算。

## 使用方式

```bash
go run ./cmd/build-claw -o claw

# 普通工作区任务：默认允许工作区文件读写，启用新任务读取记忆
./claw -dir /绝对路径/项目 -prompt '整理并创建说明文档'

# 显式选择更大的读取档位；不增加工具次数或上下文额度
./claw -dir /绝对路径/项目 -read-page-bytes 16000 -prompt '读取并整理资料'

# 严格证据报告：仅创建指定的新 Markdown 文件
./claw -dir /绝对路径/项目 -report 优化汇总.md -prompt '汇总优化建议，不修改原始资料'

# 严格只读分析继续沿用原入口
./claw -dir /绝对路径/项目 -mode readonly -analysis -prompt '分析资料并引用原文'

# 恢复沿用原任务的档位、报告配置和已消耗额度
./claw -dir /绝对路径/项目 -resume <任务ID>
```

报告首版支持 CLI、引擎 `TaskSpec.Report` 和 Bench `TestCase.ReportPath`。飞书支持读取档位配置和统一终报展示，本轮不新增聊天中的报告启动指令。

`-report` 只允许 `workspace + change`，不能与 `-analysis`、`-plan`、`-verify` 或 `-task-kind answer` 组合。路径须为工作区内的 `.md` 相对路径，父目录必须已经存在；已有目标返回冲突。报告任务只允许已注册的读取工具和唯一写入口 `write_report`，禁止裸写入、编辑、Bash 和子任务。普通 workspace 编辑行为不受报告规则影响。

## 读取档位与兼容

`read_page_bytes` 仅允许 `8000` 或 `16000`，未配置时为 `8000`。它同时决定默认读取源字节数、最大源字节数和编号正文显示上限。编号占用显示预算，因此实际消费的源字节可能小于请求 `limit`。

- `read_file.limit` 可以请求 `1…当前档位` 的较小页，省略时使用当前档位。
- `read_lines` 共享该档位，超限按完整 UTF-8 字符截断，按返回的 `next_offset` 用字节模式续读。
- `next_offset` 按实际消费的源文件字节计算，不能用行号代替。
- 子任务继承父任务档位，不能提高。恢复时显式指定不同档位会拒绝，未指定的 CLI 默认不会覆盖持久配置。
- 读取档位不改变 `-max-tool-calls`、`-max-model-calls` 或 `-context-bytes`。

Bench 支持单用例 `ReadPageBytes`；`cmd/bench -read-page-bytes` 仅给尚未指定档位的用例提供默认值。报告用例使用 `ReportPath`，不能同时配置分析、委派策略或引擎验收脚本；发布契约检查不能代替外部语义 oracle。

飞书由服务端绑定配置，用户消息不能修改权限或读取档位：

```json
{
  "event_ledger": "/绝对路径/飞书台账",
  "chats": {
    "群聊ID": {
      "work_dir": "/绝对路径/项目",
      "allowed_users": ["成员ID"],
      "mode": "readonly",
      "read_page_bytes": 16000
    }
  }
}
```

## 工作笔记与证据资格

新任务持久化 `read_context_version=1` 及可选 `ReadMemoryState`。旧任务缺少该字段时沿用原策略，不从旧文本重建证据。新任务的严格分析、普通笔记及证据报告共享来源登记与不可变原文，旧 `AnalysisState` 保留兼容读取。

普通含工具调用的响应可以附带唯一 JSON 信封：

```json
{"work_notes":{"schema_version":1,"findings":[],"processed_reads":["E1"],"summaries":{"E1":"已核对范围、适用版本、默认值和未解决问题"}}}
```

普通最终答复仍允许自然语言或用户指定的业务格式。笔记通过已有模型响应提交，不新增笔记工具、独立摘要或格式修复模型调用。无效信封不获得折叠资格；单条摘要提示目标500字节，工作笔记投影上限16 KiB，完整记录继续保存。

正文只有在完整进入成功请求、模型声明已处理、保存有效发现或范围摘要后才折叠。已处理声明不证明无遗漏，未处理材料、最新完整工具批次、关键错误和未解决原文继续保留。请求软目标96 KiB，无法安全满足时允许超出，硬上限保持有效。

同一 Agent、版本和读取区间，且原文或有效笔记仍可复用时，无目的重复请求返回 `duplicate_read` 并计一次工具尝试。有效 `review` 仍允许实际复核；父任务首次核对子任务原文不按全局覆盖拒绝。不同区间重叠会反馈新增及缺失范围。覆盖完整不等于分析正确或验收通过。

文件变化或写入效果未知撤销相关资格；Bash 进入 Handler 后全量撤销，即使最后摘要相同也不能复活旧资格。恢复运行重新取得本次依据，历史笔记只作线索。未执行的拒绝不清空有效材料。

## 报告发布与结果语义

模型通过唯一终局工具 `write_report` 提交版本化报告，报告必须是当前响应唯一工具调用。引擎保存草稿、校验来源及引用、把无效发现移入待核实、冻结渲染字节，再进入现有预览、Pending、写入、效果账本和恢复链。模型不能自行填写最终引用路径或改选输出目标。

跨文档比较必须提供两端材料、版本和适用范围；字段迁移说明旧读取位置、新位置、默认值及同步修改项；否定结论限定覆盖范围；未执行的运行效果只能列静态风险或待实测。程序验证来源、权限、版本、行号、摘录和依赖，不能通用判断迁移建议是否正确。

| 情况 | 结果 |
| --- | --- |
| 正常发布 | `NEEDS_VERIFICATION/needs_verification/2`，无需模型复述 |
| 部分引用失败且仍有有效核心 | 发布有效项及待核实项 |
| 格式无效或全部核心无依据 | `BLOCKED/report_invalid/2`，草稿保留，不写正式目标 |
| 普通终答但未提交报告 | `BLOCKED/report_not_delivered/2` |
| 已发布报告或来源变化 | `NEEDS_VERIFICATION/report_stale/2`，不重写 |
| 关键存储失败 | `FAILED/storage_error`，现场观察不能冒充持久证据 |

报告原始结构化草稿和冻结渲染材料位于现有任务材料目录，不进入全局观测日志。引用通过只表示机械依据有效，`semantic_result=not_run` 不代表语义通过；文件已写入不等于任务已验收。

Prepared 材料没有 Pending 时不自动执行；Pending 的 expected version 已存在时核对后补记回执，不重复写；已发布且版本一致时复用回执，无需新模型或工具调用。未知效果先核实，不能盲目重放。

## 交付与观测

可信产物清单仅来自确认文件回执，包含动作、相对路径及版本。CLI 按真实工作区显示本地绝对路径；飞书显示相对路径；观测台使用服务端产物 ID。观测台读取产物前核对当前摘要，文件变化时提示陈旧，拒绝路径越界和符号链接越界，不提供任意文件路径 API。

观测台分别展示报告发布状态、引用检查、语义评估、引擎验收和读取覆盖。读取记忆只投影累计记录计数，不把笔记正文复制到观测流；记录计数不代表当前可复用资格。任务文本和报告均按不可信纯文本渲染。

```bash
go test ./cmd/... ./internal/...
go test -race ./internal/...

python3 scripts/real_eval/run.py selfcheck
```

离线覆盖两档分页、未处理正文保护、无效笔记、必要复核、版本和 Bash 失效、并发归属、恢复、存储故障、报告绕过、错误引用与语义反例。固定轨迹回放只证明机制及材料体积，不冒充自由轨迹收益。

本轮按用户明确选择以 `deepseek-v4.1-flash-1017` 做主对照，覆盖项目默认真实评测模型约定。最多普通写入2对和严格报告1对，共6样本、360次模型准入；预算固定60模型、120工具、30轮、600秒、300000上下文字节。主对照统一8000档，16000档本轮仅离线比较。

先运行普通第1对，候选完整交付、质量通过且不超过12模型/40工具后才扩展。普通第2对交换运行顺序；报告对照明确比较整套报告工作流，不与普通组混算。基础设施失败停止、不自动重试，失败样本成本全部保留，未知费用为null。普通两次重复的总Token中位数下降30%为目标，尚未完成对照不得宣称达到；语义质量、机械引用和成本分别记录。
