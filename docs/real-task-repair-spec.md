# 真实任务评估修复 Spec v1

本轮实现范围是评测契约、退出结果交付、预算可见性和读取效率。保留现有 ReAct 主循环、权限模式与预算硬限制。DAG 调度、飞书持久队列、审批存储和主任务路径权限是独立后续工作。

## 实施顺序

| 批次 | 实现 | 验收 |
| --- | --- | --- |
| A | 版本化真实任务套件、独立 oracle、多维结果、证据归档 | 正反例自检，旧记录可重新解释为五次预算耗尽 |
| B | 结构化效果账本、Delivery、最终答复约束、统一终报 | 预算、取消、未知效果、持久化故障和旧日志恢复回归 |
| C | 每次请求的预算快照、探索提示、可选源码行号 | 共享预算竞态和读取分页兼容回归，再运行真实对照 |

实现前与各批次验证后的源码检查点保存到本地 `.claw/repair-checkpoints/`。检查点不包含模型凭据，不自动提交或覆盖用户原有改动。

## 结果契约

`RunResult` 保留原终态、退出码、`FinalText`、`Verification` 和 `Usage`，增加可选 `Delivery`。

```text
Delivery
  history_complete: bool
  effects: EffectReceipt[]
EffectReceipt
  action_id: string
  tool: string
  status: ToolStatus，可空
  effect: EffectStatus
  file: FileEffect，可空
FileEffect
  path: 工作区相对路径
  before_version: string
  after_version: string
```

效果账本在 `action_result` 和 `reconciled` 更新，以动作 ID 去重并保留顺序。文件路径和版本来自执行前预览及程序确认，不从工具输出文本猜测。只有已确认的文件操作携带文件回执，前后版本相同表示无变化。回执只说明动作当时或恢复核实时的效果，不能替代当前文件版本核对。

未知效果独立保留。成功退出但效果为 `UNKNOWN` 的 Bash 不能因为不在 `Pending` 中就消失。未取得结果的待核实动作同样显示为未知。旧任务缺结构化账本时 `history_complete=false`，后续动作不能消除历史缺口。

事件或关键证据保存失败返回 `FAILED/storage_error`，现场观察不能声称已持久化。事件已提交但快照更新失败时保留日志恢复路径及警告。

预算耗尽继续返回 `BUDGET_EXHAUSTED`，模型额度停止码为 `model_limit`，退出码为 3。部分交付摘要不调用模型，不执行额外工具，也不把文件写入成功升级为任务验收成功。

## 终报契约

`FinalText` 只接收模型无工具调用、非空且任务流程正常结束的答复。工具调用附带文字、失败步骤文字和错误分支文字不能作为终答。失败、中断和存储错误不发布成功式终答。

`engine.FormatRunResult` 统一格式化状态、原因、效果、验收和可展示的答复。CLI 和飞书在 `Run` 所有收尾操作完成后各发布一次终报。引擎不再调用 `Reporter.OnMessage` 发送过程文字或最终答复，接口保留兼容。CLI 保留工具进度，飞书保留审批和现有静默进度策略。飞书终报使用服务上下文与有界发送；一次发送尝试不表示远端恰好一次。

## 预算与读取契约

所有模型调用在请求构建时读取共享预算快照，覆盖主循环、规划、思考与子任务。预算块说明剩余模型次数包含本次拟请求，并计入上下文限制。快照不替代 `reserve` 的最终准入。每次重新生成，不累计旧快照，不混入自由文本工具输出。不额外预留最后一次调用，也不自动提高额度。

`read_file` 的 `line_numbers` 默认为 false。开启后显示绝对行号，行中起始标注续行；元数据头、版本和源字节 offset 语义保持兼容。编号正文上限为 8000 字节，分页保留完整 UTF-8 字符，下一 offset 按实际消费的源字节计算。编辑内容不得包含展示前缀。

## 真实评估契约

套件版本为 `real-task-v2`，独立于现有 Go Bench。公开写入限制与评分配置同源。每个样本使用独立工作区，冻结题面、夹具、oracle、二进制和启动配置。评分进程无模型凭据、无网络，执行预检失败则不开始付费调用。

R01 检查 CLI 到 write_file Handler 的有序调用链及直接读取证据。W02 明确允许共享构造文件及指定可选测试文件；独立语义 oracle 与候选测试隔离执行。候选测试必须在正确实现实际通过，并在缺陷版实际断言失败。W03 保留同一测试检出陈旧版本缺陷的要求。

每条结果分别记录产物、范围、引擎、环境、评分器维度，使用 `pass/fail/error/not_run`。多个失败标签可以同时存在，未知用量与费用是 null。范围或预算失败不短路产物检查。终态从任务记录读取，无法确定有效结果则记录协议错误。

综合通过要求运行协议有效、范围合规、独立验收通过、终态与退出码匹配、有所需最终答复且无未决动作。本轮只读用例期望 `ANSWERED/0`，修改用例期望 `NEEDS_VERIFICATION/2`。外部评分不改写引擎终态。

## 检查与发布门槛

离线运行 `go test ./cmd/... ./internal/...`、`go test -race ./internal/...`、`go build ./cmd/... ./internal/...` 和 Python 评测自检。覆盖最后一次调用写入、未知 Bash、拒绝与冲突、旧记录恢复、重复回执、存储故障、单次终报、中文及分页读取、多标签评分和汇总重建。

真实对照固定 gpt-6.1-sol，每例 8 次模型调用、20 次工具调用、30 轮、120 秒、300000 字节上下文。旧新二进制使用同一 v2 套件交错运行。

实现核对发现工作区既有默认模型为 gpt-6.1-terra，予以保留。CLI 新增 `-model` 供评估显式固定模型。旧基线没有该参数，仅接受已核实模型与二进制摘要的历史版本；未知旧二进制不能直接进入付费对照。默认模型与显式 gpt-6.1-sol 均使用现有 Responses 路径。

先运行 W02/W03 各三次双组，共 12 次、上限 96 次模型调用。新实现两例各至少 2/3 综合通过，零禁止路径变更、零虚假成功后，继续其余 18 个样本。完整对照上限 30 个样本、240 次模型调用，基础设施故障不自动重试。最终新实现要求至少 12/15、每例至少 2/3，另报产物正确率、正常收尾率和调用成本。

原 v1 的 9/15 保留为历史数据，不能与修改题面后的 v2 直接比较。实际结果与门槛是否达到，以独立保存的运行报告为准。
